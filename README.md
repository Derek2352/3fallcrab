# 3 Fall Fun 人生跌塔 · Cloudflare edition

**Play at [3fallcrab.com](https://3fallcrab.com)**

*Build your future, one block at a time.* A 3-minute physics stacking game about money choices, by **3 Fall Crab 整冧咗team** (HSUHK) for the Personal Finance Ambassador Programme 2026.

This repo is a ready-to-deploy website:

- **The game:** static files in `public/`, served from Cloudflare's edge.
- **A live leaderboard:** a small Cloudflare Worker (`server/`) with a D1 database. It keeps a weekly board (resets Monday 00:00 HKT) and an all-time board, plus the anonymised "Stats" tab.
- **`/admin`:** the survey results for your report (quiz, habits, Life Event choices, money traps, by week and month), the weekly and monthly winners with their emails, analysis-ready downloads, and Hide for unsuitable nicknames.
- **`/poster`:** a printable A4 booth poster with a QR code that points at your site.

## Deploy from GitHub (easiest, no installs)

Use the Cloudflare account that holds the **3fallcrab.com** domain. Every push to `main` redeploys automatically.

1. In the Cloudflare dashboard, go to **Workers & Pages → Create → Import a repository**. Connect GitHub if asked, then pick **Derek2352/3fallcrab**.
2. Name the Worker `freefallcrab`, the name in `wrangler.jsonc` (the live 3fallcrab.com Worker). Set the build command to `npm run build` and the deploy command to `npx wrangler deploy`.
3. Click **Deploy**. Cloudflare:
   - creates the leaderboard database on the first build, then keeps using the same one on every later build;
   - attaches **3fallcrab.com** and **www.3fallcrab.com** to the game, replacing whatever those two hostnames pointed at before (email and other DNS records are untouched);
   - keeps `https://freefallcrab.<your-subdomain>.workers.dev` working as a backup address.
4. **Open the domain to the public.** 3fallcrab.com currently sits behind a Cloudflare Access login, so players would see a sign-in page. In **Zero Trust → Access → Applications**, find the app for `3fallcrab.com` and do one of these:
   - **Recommended:** keep it, but change its path so it covers only `3fallcrab.com/admin` (add `3fallcrab.com/api/admin` too). The game is then public, and the admin page gets a second lock.
   - Or delete the application.

   Check **www.3fallcrab.com** too: on 14 October 2026 it still showed the sign-in page, so change or delete its Access application the same way. Then, in **3fallcrab.com → Rules**, create a redirect rule from the **Redirect from WWW to root** template, so every player lands on one address and keeps one best score.
5. **Set the admin password.** Go to **Workers & Pages → freefallcrab → Settings → Variables and Secrets → Add**. Choose type **Secret**, name it `ADMIN_TOKEN`, and set a long password (16+ characters). Then open [3fallcrab.com/admin](https://3fallcrab.com/admin).
   - Choose type **Secret**, not Text. Deploys from GitHub never touch secrets, so the password keeps working.
   - If Cloudflare suggests "Update your Wrangler configuration with these changes to keep deployments in sync", don't paste `ADMIN_TOKEN` into `wrangler.jsonc`: this repository is public, and the admin page shows players' emails. `wrangler.jsonc` already has `"keep_vars": true`, so deploys also keep any plain variables you add in the dashboard.
6. **Print the booth poster** from [3fallcrab.com/poster](https://3fallcrab.com/poster). Use A4 with "Background graphics" turned on.
7. **Turn on the privacy contact address.** The results screen and the page footer tell players to email **team@3fallcrab.com** to see or correct their data, or with any privacy question. Make that address reach your team (free, about 2 minutes):
   - In the Cloudflare dashboard, open **3fallcrab.com → Email → Email Routing** and click **Get started** (or **Enable**). Accept the DNS records it adds. If the domain already receives email somewhere else, skip this and change the address instead (see below).
   - Under **Destination addresses**, add the inbox that should get these emails, for example a shared team Gmail, and click the link in the verification email Cloudflare sends there.
   - Under **Routing rules → Custom addresses**, create `team`, with the action **Send to an email** and your verified inbox.
   - Send a test email to team@3fallcrab.com and check it arrives.

   To show a different address, change `config.contact_email` in `package.json` and push. Leave it empty (`""`) to hide the contact lines.
8. **Two security switches** (1 minute), in the dashboard for **3fallcrab.com**:
   - **SSL/TLS → Edge Certificates → Always Use HTTPS: On.** The site already tells browsers to stay on HTTPS, and the API refuses plain HTTP, but this sends `http://` visitors to the secure page before anything loads.
   - **Security → Bots → JavaScript detections: Off.** The site's security policy blocks the script it adds (the script changes on every request, so it can't be allowed), and no bot rule here uses it.

Link previews (WhatsApp, Instagram, Facebook) already point at `https://3fallcrab.com`; this is set in `package.json` → `config.site_url`.

## Deploy from your computer (about 5 minutes)

You need a free [Cloudflare account](https://dash.cloudflare.com/sign-up) and [Node.js](https://nodejs.org) 22 or newer. Wrangler, Cloudflare's command-line tool, won't run on older versions.

```bash
npm install
npx wrangler login      # opens the browser once to connect your Cloudflare account
npm run deploy
```

When it finishes, the game is live at https://3fallcrab.com, with `https://freefallcrab.<your-subdomain>.workers.dev` as a backup. Open it on your phone and play. The first time, Wrangler may ask before it replaces the domain's existing DNS records; answer yes.

- **The first deploy creates the database for you.** Wrangler creates a D1 database for the `DB` binding and writes its `database_id` into `wrangler.jsonc`. Keep that change (commit it if you use Git), so later deploys reuse the same database.
- **New Cloudflare account?** You may be asked to pick a `workers.dev` subdomain first. Your team or school name works well.
- **Using a different domain** (for example, another team's copy)? Edit the `routes` block in `wrangler.jsonc` and `config.site_url` in `package.json`, or delete both to use only the `workers.dev` address.

### After the first deploy

1. **Open the domain to the public** by changing its Cloudflare Access login, and turn on the security switches; see steps 4 and 8 of the GitHub steps above.
2. **Turn on the admin page.** Run `npm run admin-token` and paste a long random password (16+ characters). Then open https://3fallcrab.com/admin and enter it there.
3. **Print the booth poster.** Open https://3fallcrab.com/poster, check the address under the QR code, then press **Print poster**. Use A4 and turn on "Background graphics".

## No terminal? Drag-and-drop the game only

If you just need the game online quickly, without the shared leaderboard:

1. In the Cloudflare dashboard, go to **Workers & Pages → Create → Pages → Upload assets**.
2. Name the project, then drag the **`public`** folder in (the whole folder, not just `index.html`) and click **Deploy**.

Everything works, but scores are saved **on each player's device** only. Cloudflare's drag-and-drop upload cannot run the leaderboard code. For the live weekly board and prizes, use `npm run deploy` above.

### Other ways to deploy

- **Cloudflare Pages with Functions.** `functions/api/[[path]].js` exposes the same API as a Pages Function. Use output directory `public`, build command `npm run build`, and a D1 binding named `DB`. Cloudflare now recommends Workers for new projects, so prefer the steps above.

`npm run dev` builds `public/` and starts Wrangler. If you edit anything in `src/`, run `npm run build` again; the dev server picks up the new files.

## Accessibility

The game aims for WCAG 2.2 AA. An automated check (axe-core) finds no problems on any screen: game, Life Event cards, results, leaderboard, admin, poster and 404, on desktop and phone.

- **Cantonese for screen readers:** all Chinese text is marked `lang="zh-HK"` as it appears, so VoiceOver and TalkBack read it with a Cantonese voice. Numbers inside a Chinese sentence, like HK$3,600, stay with it.
- **Card timer:** a 10s | 30s choice on the start and pause cards. 30s gives 30 seconds per Life Event card instead of 10, and the result stays until Continue is pressed. It is remembered on the device, and screen readers hear it as a two-option choice. They are also told the time limit when a card opens. With 10s, a card result stays for 16 seconds (was 7, then 12 before the cards had stories).
- **Keyboard:** everything works without a mouse: arrows, Space, C, P, M, F in the game; 1 or 2 on Life Event cards; Tab and Enter on the results screen. Focus is always visible, and pop-ups move focus in and back out.
- **Game controller:** any standard pad (Xbox, PlayStation, Switch Pro and most others) plays the whole game: D-pad or left stick to move, A to drop, B, Y or up to turn, X to hold, LB / RB to fine-turn, down or RT to fall faster, Start to pause, Select (View) to mute. On a Life Event card X and Y pick the first or second choice (or the D-pad moves between them and A picks); on the start card, the pause card and the results the D-pad moves between the buttons, A presses, B goes back and Start starts a game. The start card shows the controller's buttons once one is connected (a browser only tells the page about a pad after one of its buttons is pressed).
- **Contrast:** text meets AA contrast. Bright backgrounds stay; text on them is ink or the colour behind white text is a little deeper. In Windows High Contrast mode the chosen card timer, the coins, the countdown bars and the selected tab show in the system's highlight colours.
- **Forms:** nickname and email have visible labels; a missing nickname or email, or a mistyped email, is announced and the field marked invalid; quiz feedback is announced. The results steps are listed in order, with the current one marked for screen readers, and each step moves focus to its heading.
- **Screen readers:** a Life Event's outcome is read with the Continue button, the coin meters read as "2 of 3", and the ⛶, pause and mute buttons keep their names and report on or off.
- **The opening film (every visit):** before the title, a 40-second stop-motion film in seven shots (`src/intro.js`, styles at the end of `src/style.css`). The shots were made with GPT Image 2 from the cast's model sheets (originals in `art/film/`, 1254 × 1254 WebP copies in `src/film/`, about 780 KB in all). After a "HSUHK 個人理財大使計劃 2026 presents" credit, Jack and Jackie start Year 1 at HSUHK, get their first pay from tutoring, then meet the 3 Falls, each with its own chapter card: buy-now-pay-later in a phone shop, a "guaranteed 30%" stranger in a rainy alley, and "I'll start saving next year" at 3 a.m. At dawn the crab sends them off to stack their life tower, the title drops in letter by letter, and the film ends on a hook: "So… what would you do? 咁…如果係你，你會點揀？", with a "Your turn 輪到你" button that starts the game. Like a film: each shot fills the screen (4:5 on a phone, with the subtitles under the picture; up to 1.85:1 on a wide screen, subtitles on it), with a slow camera move and film grain, and a different cut into each one (fade, dissolve, whip pan, lightning flash, dawn white-out). The words are written as a screenplay: each shot opens on a typed scene heading ("EXT. HSUHK CAMPUS — MORNING 外景 · 恒大校園 · 早上"), then two lines of script in Chinese and English, each naming its speaker with a parenthetical where it helps (NARRATOR (V.O.) 旁白, JACKIE, JACK (to himself), THE AD (V.O.), A STRANGER, JACKIE (half asleep), THE CRAB). The narrator sets it up ("Two first-years, one tiny budget, and forty years of choices ahead"); Jack and Jackie get their first pay and split it, Jack is tempted by HK$500-a-month and by "thirty percent, guaranteed", Jackie keeps putting saving off ("Next year came. Then the year after that."), and the crab explains the tower. A shot's second line comes part-way through it, or on a tap. The lines are real text (read out by screen readers as they come). It has its own score and sound, synthesized like the rest of the game's audio (`GameAudio.film` in `src/audio.js`), all in one key so each shot's cue runs on into the next: the projector starting, birds and a typed place name, the till and coins, the phone's heavenly glow and a receipt printing on and on, rain and thunder with a sly bass walk and coins going down the drain, a clock and a music box winding down, gulls and a drum roll, the title's hit, and a held chord on the question. A browser plays sound only after a tap, so the film offers "Sound on 開聲" (any tap turns it on), and the title's music waits for the film to end. The first picture loads with the page; the rest load in order behind the credit, and a shot whose picture isn't in yet shows its colours until it is. It plays by itself; a tap, Enter, → or A on a controller goes on; Skip, Esc or B ends it. The first tap, Enter, Space or → on it also puts the browser in full screen where it can (Android, desktop; browsers never allow it on Esc), so the title opens free of the browser's bars. The game behind is locked while it shows, and with reduced motion it cuts with plain fades and the camera holds still. `?intro=0` or `localStorage.tff_intro = "off"` leaves it out (booth staff, tests). To change a shot, replace its picture in `art/film/` and `src/film/` (square, with what matters between 22% and 78% of the height).
- **Full screen (the default):** the game opens in full screen on every device, on a title screen: the scene fills the screen, with the logo, a prize sign, a big Start button, Leaderboard and How to play pills, a Privacy pill bottom-left and a sound button bottom-right. The pills open sheets holding the page's own leaderboard, How to play and privacy sections. Tapping Start also puts the browser itself in full screen where it allows it (phones stay upright; on iPhone, Add to Home Screen opens it as a full-screen app). Leaving the browser's full screen (Esc, the back gesture) only brings its bars back. The ⛶ button (top-right on the title, in the header during play) switches to the normal page view and back, and that choice is remembered on the device. On a laptop the play area sits in a landscape scene with the status card over the sky on the left; the passbook, the directory and the rest of the page are a scroll away.
- **Full screen play, edge to edge:** in play the scene covers the whole screen with no frame round it: the sky goes on up behind the header and the status bar, the harbour on down behind the touch controls, and the city and sky on out to the sides. The header, the status bar and the controls float over it, frosted and see-through. The board box stays the play area (items never fall behind a panel); `resize()` in `src/game.js` sizes it and draws the world above and below it (`YT`, `YB`) and either side (`XV`). The page view keeps its framed board. The harbour is a strip at the bottom of the view so the tower has more of the screen: in full screen play most of it is down behind the controls (`camBase()` in `src/game.js`); the title keeps its fuller harbour. On a laptop the player in the status bar runs its full height, and the pause, full screen and sound buttons sit at the screen's top right.
- **Jack or Jackie:** after Start, players choose who they play (once per browser tab; the last choice comes up first next time). The player is a clay figure, drawn in the game (`src/avatar.js`), shown full length in the status bar (the strip on phones, the card over the sky on laptops) and in the crab's card on the desktop page view. The figure changes with the game: the life stage sets the clothes (a university tee, then a shirt and tie or a blouse and blazer with an ID lanyard, a knit or cardigan for Family, grey hair and glasses in Retirement). Money adds a patched knee when broke, a watch, then a gold watch and sunglasses. The last money decision decides what's in hand: a piggy bank for a wise pick, shopping bags for overspending, a phone with a red "!" for a scam, an hourglass for putting it off. The face shows the moment, plasters show dropped items, and a ×2 savings boost sparkles. A new outfit pops in. When the clothes or props change (a new life stage, more or less money, something new in hand, a fall), the figure flashes white and flips away in a puff of clay smoke, then flips back in its new look with sparkles; a new life stage also shows "Level up! 升級！" and more money "Richer! 身家升咗！" (with reduced motion the look simply changes).
- **The cast, photographed:** Jack, Jackie (in all four life-stage outfits) and the crab are photographed clay puppets, from character model sheets made with GPT Image 2 (`art/cards/`). `tools/cast.py` cuts them out (rembg's isnet model, with the half see-through white sneakers and socks filled in), scales everyone to one height chart, and packs them into one 200 KB picture, `src/art/cast.webp`, writing where each figure is, and where its head and right hand are, into `src/avatar.js` (between `// <cast>` lines). Once that picture has loaded, everything that draws the player draws the photo instead: the status bar, the Jack or Jackie picker, the roll, the result, the result card, the outfit-change animation. The game's extras go on top, placed by the head and hand: what's in hand (the last money decision), plasters for drops, the worried sweat drop, sunglasses when well off and the boost sparkles. The crab (logo, speech bubble, harbour) is the photo too: its smile, cheering, and claws over its mouth when worried or hiding. Until the picture loads, or if it can't, they're drawn in clay as before. The falling items are still drawn in clay: each one's picture is shaped to its physics outline, and the props on the model sheet don't match those shapes (the passbook stands up, the game's lies flat), so they need their own sheet, shot side-on to each item's outline. To change the cast, replace the sheets in `art/cards/` and run `python3 tools/cast.py` (needs `pip install "rembg[cpu]" scipy pillow numpy`; the first run downloads a 180 MB model), then `npm run clips` so How to play shows them too.
- **Who you are: the roll (like being born in 80億分之1):** before every game (after Jack or Jackie the first time), two clay slot reels decide what kind of uni student this life is: **家底 family money** (劏房 Subdivided-Flat Kid, 公屋 Public-Estate Kid, 中產 Middle-Class Kid, 富二代 Rich Kid) × **性格 personality** (卷王 The Grinder, 天才 Lazy Genius, 社交蝴蝶 Social Butterfly, 打機宅 Gamer, 文青 Café Hipster, 炒家 The Hustler). That's 24 combinations, each with a name (e.g. 劏房卷王), a nickname and a one-line roast. There are no re-rolls: a roll is kept until it's played, even if the sheet is closed. The type only changes which Life Event cards come up, never the scoring, so the prize board stays fair. Every combination has 15 cards of its own (6 for its family money, 6 for its personality, 3 for the pair) spread over the four life stages, with all three Falls; they come up about 3 in 4 times, the 16 general cards fill in, and nothing repeats in a game. A type's card wears a "為你而設 · 劏房" ribbon. The result, the result card ("Jack · 劏房卷王"), the Threads post and the laptop status card say who you rolled, and the game record keeps it (`persona`, e.g. `sub+grind`). The types and their cards are `PERSONAS` and `PERSONA_CARDS` in `src/content.js` (a card's `who` is a family-money key, a personality key or both, `sub+grind`); the roll is "who you are: the roll" in `src/game.js`. `?roll=0` (or sessionStorage `tff_roll_auto` = `1`) rolls quietly and starts straight away, for tests and a busy booth.
- **How to play shows each move, filmed from the game:** every step in How to play (steer and drop, the tower climbing to the next life stage, the roll, a Life Event card, a shock with no emergency fund, the helpers) and each of the 3 Falls has a short clip of real play beside it, about 5–9 seconds on a loop, with the on-screen pad's presses shown as tap marks. On a phone the steps are two clips side by side; on a laptop page they're one row. A clip loads only when it comes on screen, plays muted on a loop while it's there, and stops when it's off screen or a game is being played. Each has a pause / play button, and with reduced motion they show a still until played. The clips are fetched whole and played from memory, because the host answers a video's range requests with the whole file and Safari won't play a video from a server like that. All nine come to about 1.1 MB of MP4 plus small WebP stills. They're made by `npm run clips` (`tools/clips.mjs`, with the scenes in `tools/clips-scenes.mjs`): it serves `public/` on your own machine, plays each scene in a headless Chromium on a paused fake clock that moves one frame at a time (the page's CSS animations are stepped with it), so the footage is smooth and at true game speed however slow the machine, and ffmpeg encodes `src/clips/`. It needs Playwright with Chromium and ffmpeg, sends nothing anywhere, and the clips are committed, so deploys don't run it. Film them again after a visible change to the game.
- **Life Event cards as scenes of a film (three acts):** each card is a scene. Its top band is a clapperboard slate, "ACT II · SCENE 05 · TAKE 1" (第二幕 · 第5場), with a striped clapper stick that snaps shut with a clap as the card opens (held shut with reduced motion), and the 10-second timer runs out as a strip of film. The act follows the life stage: University is Act I, The Setup 第一幕：開端; First Job and Family are Act II, The Confrontation 第二幕：衝突; Retirement is Act III, The Resolution 第三幕：結局. So the first card is always Act I, and a game that ends early never reaches Act III. The scene is the card's number in the game; the take is the game's number in this visit (Play again is TAKE 2). The result tells the story in acts (below), and the result card's ticket says the act reached ("ACT III · SEAT 15F"). The acts are `ACTS` and `ACT_OF_STAGE` in `src/content.js`; the clap is `clap` in `src/audio.js`.
- **The story: what happened to Jack or Jackie next:** every Life Event card has a short "Later… 後來…" scene for each answer, in English and Cantonese. It is a little piece of the character's life after the choice, e.g. three months on, the debt from the new phone, or the old phone still working and the money saved. It shows on the answered card above the game effects, with the character's own name, and the English says she/her for Jackie. A card left to time out gets one of three "put it off" scenes. The result then tells the whole life: "Jack's story 人生故事" lists every Life Event in order under its act's heading (stage, card, how it went and what happened; "Act III never filmed 第三幕未開拍" when the game ended before Retirement) and closes with an ending, "THE END 劇終", picked by the life stage reached and how the picks went (mostly wise, mixed or mostly not), opening with the rolled type's nickname. The scenes are each card's `later` (`w` for the wise answer, `r` for the risky one) in `src/content.js`, with `LATER_NONE` and `ENDINGS`: `{name}` is Jack or Jackie, and in English `{he} {He} {him} {his} {His}` follow the character (the Chinese says 佢). A card result now stays for 16 seconds with the 10s card timer, as there's more to read; game time doesn't run while a card is open, so scores are unaffected.
- **Plain, friendly wording and type:** heights read like a Hong Kong building: G/F, then 1F, 2F… (the floor reached, never "4.6F"); the leaderboard says which dates "this week" covers (e.g. 2–8 Nov) instead of a week number; numbers in the passbook, the board and the results use the game's own rounded and body fonts (no dot-matrix "terminal" face). The status bar shows icons (a clock, a coin, a building, a water drop) instead of text labels, and the tower's ruler numbers only every 5th floor and the life-stage floors.
- **Life stages:** the tower climbs through University (from the ground), First Job (from 4F), Family (from 10F) and Retirement (from 15F); each one changes the player's clothes, the music and the Life Event cards, makes items fall faster and strings up an insurance net. The floors are `at` in `STAGES` (`src/content.js`). They were 3F, 6F and 10F until 4 Nov 2026, when everyone in the all-time top 10 was retiring; the API accepts a stage worked out the old way until 1 Dec 2026 (`OLD_STAGE_AT` in `server/api.js`), for pages loaded before the change.
- **The results, step by step:** like the title screen, the statement is a short run of steps the player presses through with Next (Back goes one step back):
  1. **Result:** the player as the game left them, the net worth counting up in big numbers (恭喜你儲到…), the stage reached, the game's 稱號 (title) with its medal, where it ranks ("贏咗 54% 玩家"), a friend's challenge won or lost, the 3 Falls and any "too good to be true" moments.
  2. **Survey:** the 3 quiz questions and a habit to commit to. The questions (since 8 November 2026) ask uni students to think: a fake trading app that wants a 15% "tax" before you can withdraw (stop paying; check the SFC register; call 18222), a phone plan's "10% flat rate" that is really about 18% a year (APR), and Ming, who saves for 10 years from 22, against Kit, who saves three times as much from 32: at 7% Ming ends with more (about HK$2.8M against HK$2.4M). The habits: auto-transfer until 6 months' expenses are saved; pay the card in full and check the APR before any instalment plan; check the SFC register and never lend an account; track 30 days, then budget. Results from the earlier quiz (renting your account, minimum payments, when to start saving) and habits are grouped into these: each earlier question's right answer counts as right on the question that replaced it, and each wrong answer under a wrong one (`was` in `src/content.js`), so the totals and the 2/3 target carry on. Next unlocks once all three are answered and a habit is picked.
  3. **Leaderboard:** a nickname and an email post the score and enter the prize draw; both are needed to post. "Skip posting" goes on without posting. A successful post moves on by itself.
  4. **Your card:** a 1080 × 1920 PNG of the result (an Instagram story's shape), made as a movie ticket: the poster untouched on top, and under it the ticket's stub. The ticket has rounded corners and a half-circle notch on each side where the poster meets the stub, cut out of the picture itself (see-through), so the downloaded file has the same shape as the card on the page. The stub has dashed tear lines, an "ADMIT ONE · 入場券" header with the programme's credit and a ticket number (from the game's end time), and at its foot a barcode, 3fallcrab.com, the date and time played, and "ACT I/II/III · SEAT" for the act reached and the best height. Some apps fill see-through corners with black or white when they show a picture. The poster is one of seven made with GPT Image 2 from the cast's model sheets (`src/share/posters/`, 1080 × 1350; the originals are in `art/posters/`), picked by where and how the game ended. A full 3-minute game ends at Retirement (with fewer than three items lost, the pile passes 15F), so the earlier stages are mostly games that ended on the third item in the harbour, and each stage has its own posters: Overspending twice (or once at University) → the trolley (使少啲，笑多啲) at any stage; at Retirement, two or more items in the harbour along the way → the rooftop (跌咗，再疊過), otherwise the ferry (疊咗一世，慢慢嘆); at Family → the studio portrait (成家，就係一齊疊); at First Job → the diner (第一份糧，先儲兩成); at University (out early) → the estate (一格一格，疊出人生) for a 劏房 or 公屋 roll, otherwise the diver (跌落海，笑住浮返上嚟). Every poster comes up in real play (a test tries every way a game can end). The panel: the 稱號 with its 3D medal and roast line; 票房 (what was saved), 場次 (the stage reached and the best height) and the 3 Falls; the billing (「領銜主演」 and the nickname, or Jack/Jackie, the rolled type, where it ranks, "挑戰成功！" when a friend's score was beaten). `posterFor` is the choice and `drawPosterCard` the panel, in `src/game.js`. The poster starts loading as the game ends; if it can't load within 5 seconds, the card is the earlier 1080 × 1350 JPEG design (the game's sky, city and harbour, the player, the amount, the 稱號 ribbon). The nickname is the board's version once posted (hidden if the filter replaced it), otherwise what the player typed; without one, the card has none. "Save image 下載圖片" downloads it; "Post to Threads 分享到Threads" opens a ready-made Threads post (see below); where the browser can share files (phones, mostly), "Share 分享" opens the share sheet (Instagram, WhatsApp…) with the same words and link. The card is made in advance, as a phone only lets a page share right on the tap.

  "See tower" and "Play again" come only on the card. A player who leaves early (Esc, or B on a pad) gets "Back to results", which returns to the same step. On a controller, Start presses Next.
- **Helpers that keep a tower standing:** three, each with a money lesson.
  - **Vine 藤蔓:** a vine-wrapped item sticks to what it touches (now and then, and for a wise answer on a spending card).
  - **Fixed-deposit lock 定期鎖:** an item in gold chain with an open padlock locks where it comes to rest. Nothing knocks it off and quakes don't shake it: "money you can't spend on a whim stays put". It comes now and then (4%), and for a wise answer on a "putting off saving" card.
  - **Insurance net 保險網:** strung across the harbour for 25 seconds, it catches up to 3 falls. A caught item floats back up in a bubble and comes back as the next item, with no drop and no loss (the iron debt ball still sinks). Lifebuoys on the net show the catches left. It comes for a wise answer on a scam card and with each new life stage: "insurance doesn't stop the fall, but it catches you".
- **Made for sharing (Threads):** what makes a browser game spread on Threads in Hong Kong is a funny verdict people screenshot, a number to brag about (the 「我算唔算已經贏咗99%香港人」 meme), a one-tap post and a friend to beat; replies and tags do the rest. So:
  - **稱號 (title):** every game gets one of 13 titles, the first whose test passes, disasters first as they're shared the most: 維港潛水員 Harbour Diver (out on the third item in the harbour before First Job; later than that, how they played names the game), 騙徒VIP (2+ scams), 保證回報信徒 (invested in the "guaranteed" offer), 先使未來錢 (2+ overspending), 明日復明日 (2+ putting off or timed out), 刮刮卡熟客 (2+ scratch cards), 零中伏神人 (no Falls, 3+ wise picks), 財務自由預備役 (Retirement), 橫財就手 (the Jackpot crab), 疊疊樂之神 (12F+), then by money: 小富翁 (HK$30,000+), 穩穩陣陣, 月光族. Each has a one-line roast. The titles are `TITLES` in `src/content.js` (the id goes into challenge links, so give a changed title a new id); the tests are `TITLE_TEST` in `src/game.js`. Each title comes with a medal drawn in 3D with three.js: gold for the brags (零中伏神人, 財務自由預備役, 橫財就手, 疊疊樂之神, 小富翁), silver for 穩穩陣陣, and a dented bronze one with a plaster on it for the disasters. On the result it drops in with a spin and sways (still with reduced motion); on the card it's a picture. It's `tools/medal3d/medal.js`, bundled with the parts of three.js it uses into `src/vendor/medal3d.js` by `npm run medal` (the bundle is committed, so deploys don't run it). The 500 KB script (130 KB over the wire) loads in the background once the title screen is idle, never during the opening story or a game, and sets itself up there too (WebGL and the shaders, the slow part of a first medal: `warm()`), so the result screen only has to draw it. It uses standard materials and a tiny painted studio for its reflections, which keeps that set-up short on a phone; without it (no WebGL, an old browser, a failed load) the result shows a flat medal and the card draws one. The game record keeps the title's id (`title`), and `/admin` shows the titles given most ("Titles 稱號").
  - **Where it ranks:** the share of all recorded games (not hidden) the score beat, from `GET /api/scores?view=pct&score=N`, shown as "贏咗 54% 玩家 · Beat 54% of players" (never "Hong Kongers" on screen; the post asks the meme as a question). It's left out offline, or with fewer than 10 games, and never says 100%.
  - **Post to Threads 分享到Threads:** a link to Threads' web intent (`https://www.threads.com/intent/post?text=…&url=…`) with the post written: the amount, the title and its roast, the brag ("我算唔算已經贏咗54%香港人？", or "只係贏咗23%人…你夠膽同我比？" below half), then "你又攞到咩稱號？👇 身邊邊個係「title」？Tag 佢！" and a challenge link. A Threads post can't take a picture from a page, so on a computer the card downloads at the same time to add to it, and on a phone the status line reminds the player to add it.
  - **A friend's challenge:** the link is `https://3fallcrab.com/c?s=score&n=nickname&v=title`. `server/worker.js` answers `/c` with the game and link previews about that result ("Ming 喺《3 Fall Fun 人生跌塔》儲到 HK$23,450，稱號「零中伏神人」— 你夠唔夠膽挑戰？", with the title's roast underneath), after checking every value (the nickname goes through the board's filter; anything else is dropped). The game reads the checked values only, so a made-up link can't put words on the screen. The friend sees a challenge note on the title, a "You beat Ming!" stamp and bubble the moment their score passes it, and on the result whether they won (and by how much they fell short); a win adds "挑戰成功！Beat Ming" to their card and "我贏咗 Ming 😎 下一個係你" to their post. The challenge lasts for the visit (Play again keeps it), and the game record marks those games (`via` = `c`), counted in `/admin` as "From shared links 經分享連結".
- **Money type 理財性格 (retired):** an earlier version also sorted each player into one of 16 personality-test-style money types. The 稱號 took its place on the result, the card and the posts. Games saved then keep the code (`mtype`), `/admin` still shows the Money types tile for periods that have some, and the names stay in `src/content.js` (`TYPES`, `TYPE_AXES`) for that.
- **Motion and sound:** "Reduce motion" turns off the shake, bobbing and card animations. Sound starts with the first tap or key press anywhere (a browser allows none sooner; until then the title says "Tap anywhere for music 輕觸任何地方播放音樂"), and every screen has a mute button. The theme plays softer, as menu music, on the title and on the results (after the end jingle), and in full during play. Every press answers with a sound: sheets open and close, Next and Back step up and down, toggles (pause, full screen, sound, card timer) click, picks (Jack or Jackie, a habit) pluck, Start and Play again ring out, a saved picture dings, a locked button says no, and any other button taps; the game's own moves keep their sounds (`src/audio.js`, wired in `src/game.js`).
- Controls are at least 24 × 24 px, and the pages fit a 320 px wide screen without sideways scrolling.
- **In an app's browser** (a result card opened from Instagram, Facebook, Messenger, Threads, LINE, WeChat, TikTok and the like; recognised by the browser's user agent): those browsers can't download a file, rarely go truly full screen, and on an iPhone follow the silent switch. So there the game:
  - shows a tip on the start: on Android a button straight to Chrome; in LINE its own "open in browser" switch; elsewhere how to use the app's ··· menu; and everywhere Copy link. Closing it keeps it closed for the visit; on a short screen the title drops its prize sign while the tip shows.
  - makes the result card a self-contained picture, so pressing and holding it saves it. "Save image" says so (instead of a download that would fail), and Share works where the app allows it.
  - on an iPhone, adds "turn off silent mode" to the "Tap anywhere for music" note (also in Safari).
- **Line breaks on any screen:** Chinese breaks between phrases, not inside one; in a line of English then Chinese, the Chinese moves down as a whole rather than taking the last English word with it; short headings (the offer titles, "Choose your player", the result title, the start card) stay on one line by shrinking a little on small phones (`fitLine()` in `src/game.js`, set by `data-fit` with the smallest size); and short texts wrap into even lines without a lone last word.

## Too good to be true

Three moments in a game look like good news. None of them is. Declining costs nothing, and keyboard 1 / 2 / Esc or controller X / Y / B answer them. Each one is saved with the game and only ever lowers the score.

- **Fake revive:** after the 3rd drop, a 10-second "CONTINUE?" offers a second go. It never works: there's no take two in life. (`troll_revive`: empty = not offered, 0 = left alone, 1 = pressed Revive.)
- **"Guaranteed 30% a month":** between 50 and 110 s an investment pop-up appears. Investing costs HK$3,000. Fake profits tick up, then a HK$1,000 "release fee" is asked and the platform vanishes. It counts as a Scam fall. (`troll_invest`: 0 = not offered, 1 = declined, 2 = invested, 3 = invested and paid the fee.)
- **Lucky scratch card:** between 45 and 150 s a HK$500 card is offered, up to 5 times. Every card is a near miss. Buying counts as an Overspending fall, and the lesson cites the Mark Six jackpot odds of 1 in 13,983,816. (`troll_tickets`: empty = never offered, 0 to 5 = cards bought.)

## The leaderboard and your data

- **Every finished game is saved, anonymously, as soon as the statement opens:** score, floors reached, life stage, items placed, each Life Event choice (card plus wise, risky or missed), how the game ended, the time and how long it really took, the character the player chose (Jack or Jackie), and what the player did with the three "Too good to be true" offers. As the player answers the quiz and picks a habit, the same record gets each quiz answer (which option, right or wrong) and the habit. The quiz shows right or wrong, with the reason, the moment an answer is tapped, and answers can't be changed after that. Nothing is ticked for the habit until the player picks one, so the pledge counts are real choices.
- **Posting to the board** adds the nickname to that same record and shows it on the leaderboard. Players who don't post still count in the survey results, just not on the board. A game posted after its week is over goes on the current week's board, so a week's winners can't change once it has ended.
- **Email (private, needed to post):** players give an email when they post, so you can contact weekly and monthly winners. It is never shown on the board, never returned by any public API, never stored on the player's device, and once saved it is never changed or cleared. Only `/admin` (behind `ADMIN_TOKEN`, and Cloudflare Access if you keep it on `/admin`) shows it.
- **What is not saved:** real names (unless someone types one as a nickname) or IP addresses. For the rate limit, a new game briefly keeps a hash of the network address, keyed with a secret and the week. It is wiped about 5 minutes later, so players can't be tracked over time.
- **If a save fails** (no signal at the booth), the game keeps the survey part on the device, without nickname or email, and sends it as soon as the board can be reached again, even if the page stays open. It counts in the week and month it was played.
- **Nickname filter:** nicknames with common English or Cantonese swear words become "Anonymous crab 匿名蟹". This includes spaced-out, full-width and l33t spellings, while names like Jason99 and Fukuda pass. Invisible-character names are blocked too. For anything else, `/admin` has **Anonymise name**, which changes only the nickname to "Anonymous crab 匿名蟹" and keeps the game in the survey results, and **Hide**, which removes the game from the board and the analysis.
- **Stats tab:** shows the share of wise choices, which of the 3 Falls players hit most, the most popular habit pledge and how many players got 2 or 3 quiz questions right. It uses the latest 1,000 games.
- **Survey results in `/admin`:** pick all time, a week or a month. You get games played, quiz takers and the share who scored 2/3 or better against the 70% target, the same share for first tries only (a device's first finished quiz, counted for games saved from 14 October 2026; replays see the same 3 questions with the answers already shown), how each quiz question was answered (and the most common wrong answer; answers to the earlier quiz are grouped in, and each question says how many), habit pledges (earlier pledges grouped in the same way), every Life Event card sorted by how often players chose the risky option (a rolled type's cards say which type they're for), the 3 Falls, life stages reached (games before 4 Nov 2026 used the old stage floors, see Life stages), and week-by-week and month-by-month trends. Hidden games are left out.
- **Winners:** `/admin → Winners` lists the top scores of any week or month with their emails, with copy buttons, and flags a player who appears twice. Each row also shows the items placed, seconds actually played and items dropped. A full 3-minute game that took more than 4½ minutes of real time is marked "slow motion: check": a slow or throttled device makes the game easier.
- **Downloads for your report** (`/admin → Downloads`, Excel-ready CSV):
  - `games.csv`: one row per game, with each quiz answer (grouped onto the current questions; `quiz_version` says whether the game saw the earlier or the current quiz, and `habit` names the grouped habit while `habit_id` keeps the one picked) and each Life Event choice in its own column, then `items_placed`, `seconds_played`, `quizzes_before` (quizzes that device had finished before; 0 is a first try), `jackpot` (1 = the Jackpot crab came up in that game), `troll_revive` (empty = the fake revive was never offered, 0 = declined, 1 = pressed Revive), `troll_invest` (0 = no investment pop-up, 1 = declined, 2 = invested HK$3,000, 3 = also paid the HK$1,000 fee), `troll_tickets` (empty = no scratch-card offer, 0 to 5 = cards bought) and `player` (`jack` or `jackie`, the character chosen; stored as `avatar`), `money_type` (the 4-letter money type, stored as `mtype`; only games saved while the game had money types), `money_type_name`, `via` (`c` = the player opened a friend's challenge link), `title` (the game's 稱號 id), `title_name`, `persona` (the rolled type, e.g. `sub+grind`) and `persona_name`. The three `troll_` columns, `player`, the money type, `via` and `title` are empty for games saved before they were added. The overview also counts the titles given most ("Titles 稱號"), the types rolled most ("Rolled as 抽到嘅身份"), the money types for periods that have them ("Money types 理財性格") and the games started from a shared challenge link ("From shared links 經分享連結").
  - `quiz_answers.csv`: one row per quiz answer, as asked (an earlier question keeps its own wording), plus `grouped_question_no` and `grouped_answer`: where it counts on the current quiz. Pivot it by question to see which questions and wrong answers trip players up.
  - `life_events.csv`: one row per Life Event decision. Pivot it by card, life stage or trap.
  - `Raw CSV`: every column exactly as stored.
  Every file has a `hidden` column; keep the rows with 0 to match the dashboard. Games saved before 9 October 2026 have the quiz total only, not each answer; the dashboard notes how many. The last three `games.csv` columns are empty for games saved before 14 October 2026.
- **Prizes:** scores are reported by the player's browser. The API turns away games the rules make impossible (more points than the items placed and floors reached allow, a life stage that doesn't match the floors, more than 7 Life Event cards), but a careful cheat could still fake a believable one. Before handing out a weekly prize, check the row in Winners and ask the winner to show their end-of-game statement or phone. Hide anything suspicious in `/admin`.
- **Free-plan limits:** Workers gives 100,000 requests a day. D1 gives 5 million rows read and 100,000 rows written a day, enforced since 1 Sept 2026. One game is one score post, and the board refreshes only while it's on screen (every 45 s). A busy booth day is far below these limits.

### Updating the live game without losing scores

Pushing to `main` redeploys only the code and the files in `public/`. The scores live in the D1 database bound to the Worker as `DB`, and every deploy keeps using that same database, so the leaderboard carries on untouched. Scores saved on players' phones use fixed storage keys, so updates keep those too.

What could reset the board, and what stops it:

- **Renaming the Worker or the `DB` binding.** Changing `"name"` in `wrangler.jsonc` (`freefallcrab`) or the `DB` binding makes Cloudflare create a new, empty database. `npm run build` refuses to build if either changes, so a GitHub deploy fails safely instead of going live.
- **SQL that wipes the table.** The build also refuses `DROP TABLE`, `TRUNCATE` or a `DELETE FROM scores` without `WHERE` anywhere in `server/`, `functions/` or `migrations/`.
- **Changing the table later.** Only ever add columns; never remove or rename them. New columns go in `ADDED` in `server/api.js`: the API adds them to the live table by itself on its next request, keeping every row.
- **Deleting the database in the dashboard.** Don't. To stop new scores after the event, set `LEADERBOARD_CLOSED` to `"1"` instead; the board stays visible.

If you ever really want a brand-new board, run the build with `ALLOW_LEADERBOARD_RESET=1`.

**Backups:**

- **Quick:** `/admin → Download CSV` at any time.
- **Full SQL copy:** find the database name in the Cloudflare dashboard under **Workers & Pages → freefallcrab → Bindings** (the D1 database bound as `DB`), then run `npx wrangler d1 export <database-name> --remote --output backup.sql`.
- **Undo a mistake:** D1 Time Travel can roll the database back to any minute in the last 7 days on the free plan (30 days on paid): `npx wrangler d1 time-travel restore <database-name> --timestamp=2026-10-09T12:00:00Z`.

### API

| Route | Use |
|---|---|
| `GET /api/health` | Is the database connected? |
| `GET /api/scores` | This week's top 10 and the all-time top 10 |
| `GET /api/scores?view=stats` | Anonymised totals for the Stats tab |
| `GET /api/scores?view=pct&score=N` | `{pct, n}`: the share of recorded games (not hidden) scoring below N, for "beat N% of players" (`pct` is null under 10 games, at most 99) |
| `GET /c?s=&n=&v=` | A friend's challenge: the game, with link previews about their result (not an API; see Made for sharing) |
| `POST /api/scores` | Save a finished game, then update it with quiz answers, habit, and the nickname and email when posting. Validated server-side; the score can't change after the first save |
| `GET /api/admin/summary`, `/winners`, `/rows`, `/scores`, `/export`, `POST /api/admin/hide`, `/rename` | Admin: survey analysis (`?week=` or `?month=`), winners with emails, every game for the downloads, the games list, raw CSV, hide, anonymise a nickname. Needs the `Authorization: Bearer <ADMIN_TOKEN>` header. After 20 wrong passwords from one network in 15 minutes, that network is locked out for up to 15 minutes |

The API works over HTTPS only: plain HTTP is redirected (reads) or refused (saves), and every response tells browsers to stay on HTTPS. The database table is created automatically on first use. `migrations/0001_create_scores.sql` holds the same schema if you prefer `npm run db:migrate`.
